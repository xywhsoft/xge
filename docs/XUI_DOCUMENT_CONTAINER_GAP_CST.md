## 实现

将既有列表块间补丁扩展为私有 `doc_markdown_container_gap_source_patch`，接受 ROOT、QUOTE、FOOTNOTE 和 LIST_ITEM 的非首间隙。语义计划必须只新增一个段落，旧子节点的 ID 和顺序必须保持。

物理插入边界仍来自相邻块 CST 和 SourceLine；列表沿用解析器确认的 marker、task gap 与逻辑内容列。其他容器在已有段落中取物理前缀样本，复用统一的 `doc_md_paragraph_prefixes`。该前缀计划仅消费空白和已确认的祖先标记，不把格式或链接开头当作容器前缀。序列化内容限定为新增段落与必要的新边界，旧块和旧来源间隙保持原字节。

候选必须完整重解析，保留不可编辑定义的原拼写，并与独立语义意图比较所有节点、属性和资源。受影响列表的派生 TIGHT 位仍由既有计划记录明确的属性操作；没有忽略整树属性差异。来源、语义、caret、通知和历史继续属于同一个事务，失败/取消不能发布半成品。
