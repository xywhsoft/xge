# Document 来源存储回收

日期：2026-10-04。范围：K3/K4，以及验证中发现的空 Markdown 根节点一致性问题。正式源码、实际 DLL、Linux 与浏览器完整批次验收通过。整体重构目标保持进行中。

## 已确认的问题

上一正式 DLL 的独立公开探针：脚注正文从 1 MiB 删除到 64 字节，源码仅剩 143/152 字节，清空历史和快照后，CurrentBytes 仍为 1,056,358/1,060,407。SourceStore 的短切片继续持有已删除的大 Blob。这是当前版本存储的真实占用，不是保留 Undo 或 Snapshot 所需的占用。

碎片候选另确认，小于 4 KiB 的语义文本 Blob 也会累计保留大量删除内容：96 个 3 KiB 插入/删除循环后，3,078 字节源码的 CurrentBytes 为 344,903，其中来源 payload 已回收到 3,078，但语义文本存储仍为 316,742。原失败日志保留。

空文档独立探针还确认，新建 Markdown 根节点的 syntax 范围是无来源，而删空后完整解析的范围是 0..0。二者应具有相同的空源码语法范围。

## 实现

Document state 增加私有来源 payload 上界。新插入字节增加上界；删除不直接扣减，避免把仍被切片持有的存储错误计为已释放。来源超过 4 KiB 的估计占用且逻辑长度不足其四分之一时，在解析候选中扫描实际存储并回收低占用块；成功后记录精确 payload 数量。普通小修改只更新一个标量，不新增全篇来源扫描。

Prepare 输入同时保存该不可变上界。Continue 读取输入来源和对应上界，不读取正在运行的 builder；VISUAL shadow、完整解析、reconcile 和原生加载统一维护同一字段。覆盖度扫描和复制在解析路径上进行，Prepare 创建不执行此新增回收扫描。

共同字节序列回收按每个 Blob 的全部切片累计保留量。低于四分之一时仅复制保留片段，密集块继续共享；多个短切片共同保留大块时不会误判为稀疏。来源和语义文本都覆盖小 Blob，避免大量小块共同积累被删除的正文。计数、收集、原地堆排序和复制均检查取消；失败不会替换调用者的来源根和存储上界。

新建 Markdown 根节点直接使用 0..0 的空语法范围；Rich 初始化保持其语义来源规则。无需为了初始化空 Markdown 制造一个编辑事务或历史步骤。

公共 API、ABI16 与原生格式7不变；没有兼容包装。

## 当前候选证据

- 42 个公开场景：4 KiB/128 KiB/1 MiB，已使用/未使用脚注，SOURCE、Prepare、queued/ready Continue、原生重载、删空和累计删除。独立全文重载核对完整语义、来源、语法和全部有序定义，Undo/Redo 与独立内存集合核算通过。
- 上述场景 CurrentBytes 小于 64 KiB；原两条 1 MiB 探针降为 7,919/11,968 字节。保留旧快照期间旧内容仍由 Snapshot 正确计费；释放 Document 后两个快照继续与独立重载相等，释放旧快照后存活存储小于 128 KiB。
- 96 个不同的 3 KiB/8 KiB 存储块、192 个顺序补丁，分别通过 SOURCE 和 worker Prepare；最后 3,078 字节源码的 CurrentBytes 为约 32–53 KiB，来源 payload 为 3,078。该成本包含持久树节点，不表示所有文档都只占源码字节数。
- 已使用/未使用脚注各一例，在 Run 已进入 RUNNING 且 worker 暂停时 Continue；旧候选返回 STALE，新候选完成回收并与全文重载相等，无泄漏。
- Prepare 362 个 OOM、340 个取消点，来源、语义、版本、保存标记与历史原子。另有 512 个短切片的共同覆盖度验证，保留旧不可变根并核对实际字节和独立 payload 数量。
- 候选完整 Core、持久字节共享专项、Linux ASan/UBSan/leak 检查，以及 sequence_share/store/markdown/reconcile/prepare/io 六个 analyzer 通过。
