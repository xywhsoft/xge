# 实体内部跨块选区的 Markdown 来源编辑

本项补齐统一 Document 的来源保真和语义选区编辑，服务于整体方案的 K2/K4/E1/M1。实现和测试目前位于独立候选，尚未合入主工作区；不能据专项通过宣称工作包或整体重构完成。

## 问题与内核改进

Markdown 命名实体可以展开为多个 Unicode 标量，例如本地 MD4C 实体表中的 `&NotEqualTilde;` 展开为 U+2242 与 U+0338。可视模式能够选择这两个标量之间的合法文字位置，但这个位置不对应实体原拼写内部的精确字节边界。

原部分跨块写入器在选区端点位于实体内部时，没有同时规划左右段落的行内格式闭合、开启范围。在独立旧产品对照的54个场景中，48处未保留预期原拼写，6处返回无法表示。实际Editor三模式162个对照也检出相同48处差异和6次拒绝，其他1,638个父Editor场景通过。

新写入器继续使用现有 Document、解析器确认的来源范围和同一事务：

1. 跨块选区无论端点是否在实体内部，都规划左右行内闭合和开启链。
2. 左侧保留的实体标量在原左格式内写出；右侧保留的标量在右格式重新开启后写出，避免进入错误的格式归属。
3. 被分割的实体片段采用现有标量实体写入函数；其他实体、引用定义、容器、标题和空白保持原字节。
4. 发布前仍需完整重解析、整树语义、来源索引、定义保护和事务原子性证明。

未增加内容模型、公开API或旧API兼容层，也未放宽已有语义或原字节断言。
