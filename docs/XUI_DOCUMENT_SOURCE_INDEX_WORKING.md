日期：2026-10-05。所属 K2/K3/K4，与解析器确认的容器缩进来源联合合入。原整体重构目标及 13 个工作包保持；当前 207 项输入保持原样；Windows/Linux Core 正式验收失败，修复与重新验收待完成。

## 问题与实现

混合引用、任务列表、格式、嵌套图片与链接的 4096 容器样本只有 352,256 源码字节，但父候选完整 DLL 的来源索引构建峰值达到 100,663,832 字节，超过默认 64 MiB 工作预算。这里的峰值不含已有快照，包含分配头及扩容时旧、新缓冲同时存活的开销。

临时注释原来保存完整公开 Token，重复保存快照中已有的 NodeId、来源映射和解码字段。现在只保存范围、归属序号、种类/标志和扫描优先级；在已验证的范围内打包种类，范围与来源序号保持 64 位。64 位构建中注释从 104 字节缩为 48 字节，公开解码继续读取同一不可变快照。

扫描事件的原偏移保持 64 位。利用既有注释数量上界，将事件开始/结束标志与注释序号合并，事件从 24 字节缩为 16 字节；保持同位置结束优先及原序号顺序。只在来源角色收集阶段使用的归属区间缓冲，在事件扫描前释放，避免两个独立阶段同时占用内存。

没有提高默认预算，没有额外 SourceStore、可写 Document 或撤销历史；公开 API/ABI 与原生 schema 7 保持。保留索引的大小没有改变，完整复杂大文档性能仍有欠账。
