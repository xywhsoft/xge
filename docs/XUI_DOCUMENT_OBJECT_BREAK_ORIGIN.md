## 正确性问题

图片 alt 拥有文字，没有独立 SoftBreak/HardBreak 节点。旧采集器因此跳过解析器的 break 来源 hook，从之前的文字游标扫描换行。格式闭合标记会被错误计入来源；alt 首行为空时，游标还可能属于前一段。两个实际 DLL 的独立 72 场景探针均有 63 个范围错误；其中第二个使用当前 front matter 正式 DLL，证明该差距仍存在。

## 候选实现

普通 break 与文字对象的归一化换行共用解析器确认的 trailing、hard marker 和原始行结束范围。文字对象先追加语义换行，记录对象及文字偏移；随后由同一 hook 附加 normalized 来源片段、更新游标和父范围。该逻辑不从正文拼写或之前文字位置猜测范围，不新增公共 API、结构布局或原生文件格式，也不建立独立内容或历史。
