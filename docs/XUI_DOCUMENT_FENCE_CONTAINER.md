## 问题与根因

207 项的容器缩进来源与 SourceIndex 工作内存联合批次，在 Windows 完整套件和 Linux Core 均实际退出 1。文字归一化来源差分 fixture=4、LF、byte=21 插入反引号时，源码替换返回 `XUI_DOC_ERROR_FORMAT`（-105）。同一 Linux 可执行文件及 Windows 源码诊断均复现，不能归因于环境或预算。

一个围栏代码块的外层引用或列表不再匹配后，解析器仍运行结束围栏探测。该探测即使失败也会推进输出偏移。部分反引号因此被消耗，后面的 `>` 被当作新引用标记，而记录的缩进起点仍位于反引号前。严格来源校验正确拒绝了这个包含非空白字符的范围。完整围栏也可能被误当作旧块的结束标记，而不是外层的新代码块。

修复将围栏继续及结束判断限定于全部祖先容器显式匹配的情况。祖先结束时，从原始、未被探测消耗的行继续普通块分析。实际文字、完整新围栏与新容器都由同一解析路径识别；保留严格缩进检查，没有来源回退、内容删除、额外 Document 或兼容包装。
