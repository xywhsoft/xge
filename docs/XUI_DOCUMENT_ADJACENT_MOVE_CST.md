## 问题与实现

六个独立原始字节黄金覆盖正文紧邻引用、列表项和脚注尾部时移入，
以及这些容器尾段移到紧邻的下一正文块。原 v89 的实际运行检出三处
源码/历史差异和三次 -107 拒绝；完整 HTML 的三个成功场景仍等价。
这说明只核对内容或 HTML 不能证明编辑保留源码。

在同一 Document/SourceStore 写入器中修复三项：

1. 切除区间采用半开范围，只拒绝严格内部插入点。起点与终点是合法
   相邻插入间隙；切除后，原终点也必须减去切除长度。
2. 最后一个容器子段落移动时，扫描紧随容器语法范围的物理空白行，
   使分隔随段落移动。目标容器尾部插入同样放在已有分隔之后，避免
   脚注内两个段落合并或在移出后增加空行。
3. 扫描仅跨越普通空白行，在任何非空行、隐藏定义或容器标记前停止。
   继续使用持久片段，不按语义显示顺序推断物理来源范围。

每行扫描沿用已有取消检查；完整重解析、整树语义、稳定身份以及所有
非编辑定义原拼写保护保持。列表松紧派生属性仍只在两条受影响祖先链
独立计划并验证，没有放宽发布条件，没有新文档或兼容 API。
