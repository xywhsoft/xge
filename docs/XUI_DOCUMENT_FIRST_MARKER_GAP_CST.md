# 脚注与列表引用首行标记的无损编辑

本批继续 K2/E1：富文本与 Markdown 共用 Document、事务、来源存储和历史。产品候选位于独立工作目录，主工作区 v15 与此前冻结产品不修改。

## 问题与修复

在第一个代码块之前输入段落时，脚注定义头、列表中的引用标记和脚注中的引用标记可能与旧代码共用一条物理行。首行前缀包含列表或脚注头，续行前缀没有这些头；直接复用续行前缀会改写旧缩进代码、围栏及原始标记。

扩展同一个 `doc_markdown_container_gap_source_patch`，允许非空 FOOTNOTE 的首间隙，并从第一个旧子块读取解析器确认的物理来源。首行与续行前缀不同时，只在来源边界和前缀长度均得到证明后移动首行前缀：新段落使用原首行头，其后写必要分隔，再将原续行前缀放回旧代码之前。旧代码文本、共享 Tab、围栏和信息字段不重写。

脚注头本来独占一行时，保留这条空头，在代码之前的续行插入段落，不将它改成新的首行正文。新增段落的 padding 与旧代码的原续行前缀分开保存，避免将新 padding 注入旧代码。

所有候选仍必须经过完整重解析、全部语义属性与资源比较、隐藏定义保护，再由根事务原子发布。列表松紧变化只通过已有显式属性计划进入共同历史；未放宽语义证明或失败原子门槛。
