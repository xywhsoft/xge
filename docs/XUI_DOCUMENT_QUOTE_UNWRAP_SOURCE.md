# Document 取消引用的来源保真

更新：2026-10-04。对应整体设计 §6.2 的最小安全来源补丁、§5 的持久共享，以及 K2/E1 的结构命令正确性。整体重构尚未完成。

## 已复现的问题

前批封存 DLL `build/source-sharing-20261004/native-final/xge.dll` 的 `xuiDocumentTxnUnwrapQuote` 会进入通用容器序列化。实际先失败记录把 `&amp;` 改成 `\&`、把四字符代码围栏改成三字符围栏，并丢弃围栏语言之后的附加信息。当前维护测试重新编译后，旧 DLL 仍实际退出 1，见 `validation-2026-10-04-quote-unwrap-before-dll-v2.log`。

只按字节删除 `>` 也不正确：Tab 的宽度取决于所在列，引用可能位于列表的内容列，后面还可能有子引用或列表标记。取消父引用后，未经调整的缩进 Tab 会改变代码正文或子块结构。

## 实现

MD4C 的私有引用前缀回调记录每条显式引用行的六个量：标记/缩进结束的来源偏移，以及本层缩进起点、标记、正文起点、缩进结束的逻辑列。初始引用和续行均在解析器实际消费前缀时采集；不通过扫描正文猜测语法。原有公开引用标记位置及 `quote_prefixes` 格式保持不变，完整列信息放入 Quote 的不可变 `syntax_aux`，无需改变公开 API、ABI 或原生文件版本。

取消整块引用采用专用的受检来源写入器：

- 根据解析器记录确定本层所属缩进、`>` 和一个可选逻辑空格。位于 Tab 内的边界只拆分该 Tab，保留父容器前缀。
- 收集子引用及列表项已经确认的标记区间，按来源顺序合并；调整这些缩进区间中因列变化而宽度变化的 Tab。代码中的字面 `>`、正文 Tab 和其他非前缀字节原样复制。
- 延用来源复制证明与稀疏补丁执行器，从后向前只修改复制区间之间的空隙；延迟到候选完成后解析一次。
- 完整语义树与全部有序链接/脚注定义值相等才接收候选，包括重复、未使用定义与脚注代码正文。语义不符时仍采用既有受检容器路径；失败、OOM、取消均不能发布部分修改。

当引用中的多个块提升为列表直接子块时，保留的空行可能使列表变松散。命令在构造目标语义时同步这一属性；没有空行的段落与围栏组合仍能保留紧凑列表。Rich 分支在提升连续段落时也调整列表间距。

## 边界与后续

该路径处理完整 Quote 的前缀移除，仍不是完整 CST。与相邻段落重新分隔、提醒块的专用头部、位于脚注正文内部的结构修改、部分范围取消引用，以及其他复杂结构命令尚需继续完善。完整语义和定义检查保留这些边界，未证明的来源仍走既有受检容器路径，不能据此宣称所有取消引用都已无损。

来源写入与完整解析仍有临时缓冲；正文规模无关的历史存储不证明 P95 延迟达标。CommonMark 语料的现有验证证明解析、来源、原生往返和差分，不证明 HTML conformance。Linux Renderer/View 使用无窗口代理，真实后端、IME/读屏、DPI、其他平台、整体命令/转换/迁移和固定机器性能验收继续保留。

通用 WebView 仍为 Windows 基础网页承载；其他四平台和公共 JS/消息通信按用户决定暂缓。Document 内部公式、Mermaid、HTML 渲染及独立 HTML 交互继续单独验证。
