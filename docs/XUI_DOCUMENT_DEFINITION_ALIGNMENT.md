# Document 定义中段对齐与共享

日期：2026-10-04。范围：K2/K4/K3 的链接、脚注定义值缓存对齐和持久字节共享。正式源码、实际 DLL、Linux 与浏览器完整批次验收通过。整体重构目标保持进行中。

## 已确认的问题

上一正式 DLL 在一个 Prepare 中同时修改前后的小定义并插入新定义时，即使中间 1 MiB 的脚注正文完全未变，HistoryBytes 仍为 1,054,980/1,057,823。旧实现仅保留数量变化后的相同前后缀，未匹配的中段被重新持有。同步 SOURCE 逐补丁解析的原控制探针通过，不应把它描述成失败。

初版候选按类型、完整值和标签建立索引后解决了上述问题，但同标签、同大小且正文不同的两个定义重排并各修改一个字符时，缓存独占历史仍为 263,782 字节。大小与顺序不足以推断旧值。新的共同输入池将该 128 KiB 双正文探针的缓存独占历史降至 1,440 字节。

同步 SOURCE 还有额外情况：前一个补丁可能暂时删除后一个补丁要移动回来的值。最终实现从不可变事务起点补充同类型、同原始标签的旧值；完整解析和已修改缓存的增量解析均接入，避免只从中间状态寻找字节。

## 实现

先保留经过类型和完整字节核对的前后缀。中段建立临时完整值与标签索引；哈希仅定位候选，相等判断仍检查类型、长度和全部字节。连续匹配的旧序列范围整体复用；重复值优先延续相邻顺序，通过二分定位重复组而非逐条线性试探。

改变的值优先选择同类型、同标签的输入。存在多个可能旧值时，临时组池将旧字节序列连接为不可变 rope，交给共同字节匹配器寻找并证明可共享范围。池只借用已有 payload，不复制整个旧正文，不成为发布后的定义元数据；取消或失败释放全部临时路径。同步 SOURCE 的池可补充事务起点的值，读取起点标签时不扫描完整正文。

新解析器决定最终定义内容、顺序和来源坐标，包括未使用与重复定义。共享的是不可变字节内容，不是定义身份；同名链接和脚注按类型区分。空中段插入/删除和单个普通值修改保留直接路径。

公共 API、ABI16 与原生格式7不变；无旧 API 兼容包装。

## 已通过的验证

- 192 个公开 SOURCE/Prepare/queued 和 ready Continue 场景：4 KiB/128 KiB/1 MiB、已使用/未使用脚注，插入、删除、等数量替换、重排、改变大重复正文、类型混合与标题有无。
- 24 个同标签同大小双正文重排场景：两个不同正文同时改动，另增加定义；四种编辑路径均通过，缓存独占历史为 1,440 字节。
- 128 个交错且内容重复的链接/脚注定义组，普通与原生重载、Prepare 和 ready Continue；另有两个 1 MiB 原生重载编辑场景。
- RUNNING worker 暂停期间 Continue：旧工作返回 STALE，新工作与完整独立重载相等，无泄漏。
- 每个功能场景核对实际源码、完整语义树、来源/语法信息和全部有序定义；Core 还逐项核对私有值缓存和独立 allocation 集合。Undo/Redo、保存标记和释放 Document 后的快照继续有效。
- Prepare 1,185 个 OOM 和 935 个取消点；双正文 SOURCE 1,809 个 OOM 和 1,797 个私有取消点，来源、版本、内容、历史及保存标记保持原子。实际 DLL 执行公开 OOM 和 Prepare 取消；同步 SOURCE 无公共取消令牌，其私有取消专项由 Core 验证。
- 强制所有完整值与标签哈希为零的同一维护测试通过；普通及碰撞版本 Linux ASan/UBSan/leak 检查通过；完整 Core、原字节共享、来源回收回归及两个修改模块 analyzer 通过。
- 七项正式源/头文件与维护套件输入落地；候选 16 条检查和实际 DLL 13 条构建/专项命令均实际退出 0。正式 DLL 原 1 MiB 中段探针的 HistoryBytes 为 5,836/8,679。

重复定义移到前面会改变生效正文，Undo 必须保留被替换的语义正文。因此这种情况下总 HistoryBytes 的门槛包含旧正文大小；定义缓存仍单独要求小于 32 KiB。没有通过放宽缓存门槛掩盖重复复制。

早期测试随机正文碰巧包含 last，导致测试自身错误替换；修正为完整定义标记。另一个早期失败是未把合法的旧语义正文计入 Undo 预算。原测试、失败日志与调整理由保留。旧实际 DLL 测试使用已记录指纹的 v4 测试；后续新增组池及事务起点测试没有被冒充为同一旧测试输入。
