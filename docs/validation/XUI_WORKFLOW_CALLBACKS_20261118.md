# Owned Workflow node callbacks

`xuiWorkflowRegisterNodeTypeOwned` accepts the new size-prefixed descriptor on
an owned Workflow. The legacy callback descriptors and entry points keep their
ABI. The new descriptor shares one user pointer across the two callbacks.
With an owner record, the registry holds one reference, traces it alongside
the configuration schema, and drops it when the Workflow finalizes. Native
callers may omit that record when they manage the lifetime of their code and
user data independently.

The node and writer pointers are valid on the creator thread for the duration
of the callback. `xuiWorkflowCallbackConfig` returns read-only borrowed
configuration. Workflow and its associated Graph return Busy during callback
dispatch and owner Hold or Drop. Both callbacks are invoked once per node
operation. The port result grows as needed. The legacy entry point retains
its capacity negotiation.

Writers copy text before returning to callback code. The first writer failure
invalidates that callback's staged output. Configuration and dynamic ports
are committed together after preparation. Validation transfers staged
diagnostic text into the Graph after one reservation for the entire diagnostic
batch. A failed callback publishes none of its rows. Other diagnostics
generated by the validation pass follow the existing Graph contract.

The source fixture in
`tests/xui/xui_workflow_callbacks_owned_test.c` exercises Hold rollback,
registration and trace, Busy, single dispatch with 40 rows, callback-local
text, writer OOM and checked consuming release. The six Workflow/model
fixtures build and pass under GCC C11 at O0 and O2 on Windows and Linux with
the matched xlang XRT. They use a CPU-only model.
