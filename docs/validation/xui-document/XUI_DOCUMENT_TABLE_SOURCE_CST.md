## 实现与证据

当前主工作区正常 DLL 已确认：省略边缘管道符的表格插列会回退为整表重写，改变未编辑的 `:--:` 和原始边缘拼写。修正临时驱动的缓冲区容量后，编译退出 0、运行退出 1，命中独立原字节断言，见 `build/source-document-table-20261006/root-proof-v2.json`。最终加强驱动也在原正常 DLL 触发同一源码黄金失败。

候选从现有 MD4C 同一次已接受表格解析中采集原始行和全部物理单元格，包括空单元格、多余且语义忽略的单元格。语义单元格和来源描述共用空白裁剪规则；CST 保存原范围、内容范围、行号及物理列号。记录属于原不可变 Document 的正文或定义 arena，不另建解析器、源码副本或语义 NodeId。

内核新增借用语法游标，统一查找、读取普通正文和隐藏定义中的块。列命令通过这些槽生成倒序来源补丁；缺少的尾部单元格继续由表格宽度隐式提供，不强制写入源码；多余单元格的未操作字节保留。必要时补足边缘管道符，避免原始空单元格在重新解析时消失。已使用脚注内的命令只允许修改选定正文，保留定义标签和其他定义。仍进行完整语义核对，失败和 OOM 不发布。

表格来源描述是透明范围绑定，不替代原文字、标记和空白归属。完整入口在 v3 检出了将 `SCOPE` 错误写入字节分区的问题：Linux 常规入口和实际 Windows DLL 均触发原 `source_index_test.c:117`。v4 改用来源构建器的零类型范围，仅在发布重叠绑定时转换为公开 `SCOPE`；内容子范围也不提高透明绑定的分区优先级。新表格驱动永久断言字节分区类型上限。精确加强驱动在 v3 两配置各编译 0、运行 1，命中指定类型断言；v4 两配置通过，失败证据保留。
