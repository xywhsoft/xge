## 实现与边界

跨块选区两端落在文字内部时，保留左侧文字前缀和右侧文字后缀。统一 Markdown 写入器使用解析器采集的行内来源归属，复制左端所需的关闭链和右端所需的开启链，删除真正选中的来源区域；不重新序列化整个容器。显式与隐式引用继续使用原定义键和定义保护。

左端 CODE 的新文字按字面写入，反引号碰撞通过同一代码分隔符计划处理。关闭链中被选区覆盖的代码关闭部分与新分隔符共同更新，外层格式关闭链继续保留。标题合并保留左标题的 ATX/Setext 来源骨架，保留右端终止换行或 EOF。

非空单行替换和空替换共用上述归属计划。空替换只对真正的部分跨块选区启用新计划，既有精确块接缝路径保留。删除后，右侧格式标记可能改变分隔符的左右结合条件：首次完整解析与目标语义不等价时，仅尝试把左端最后一个字符的精确、未经转义的来源编码为字符实体；原字节和文字字节必须相同，且不能处于 CODE。重新完整解析后仍须证明整树语义、定义、索引和历史正确。该边界改写通过实际来源操作报告。

当前范围是同父容器、两端来源精确的文字选区。多行新输入、实体内部折叠位置、跨父容器及非文字选区的完整命令矩阵仍待补齐，不能由本项通过推断全部范围已完成。

- 实际旧 DLL 的非空 60 个严格对照检出 56 处来源差异、4 处拒绝；新独立写入器已在同一黄金中消除这些问题。

- 空替换第一版黄金中 `ke**!cd**` 不具有预期的右侧加粗语义，导致严格语义核对提前失败。新黄金显式使用 `k&#101;**!cd**` 保留文字与格式；原失败保留。修正后的旧候选 30 个对照完整执行，检出 28 处来源差异、2 处拒绝。
- Editor 第一版驱动未捕获描述符 `onError`，把事件分发与空闲 Flush 成功误认为命令成功，在第一个拒绝的脚注场景失败。新独立副本捕获实际命令错误，未删除或放宽任何黄金；旧 DLL 的 270 个场景全部执行，检出 84 处来源差异、6 处拒绝。该记录是旧产品负例，不是新候选通过。
