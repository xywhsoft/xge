## 问题和证据

先前容器间隙来源计划依赖已有段落提供前缀样本。容器只有缩进代码或围栏代码时会回退到较大范围序列化，改写未编辑的代码语法、围栏信息或前缀。

十个有效根文档/引用/脚注/列表内引用/脚注内引用、缩进/围栏样例的独立来源诊断确认十处差异。最初脚注缩进样例错误地在定义头首行直接放置代码；解析器实际将其视为段落。原输入和失败保留，后续使用独立头行与八空格续行，并在命令前确认 CODE 语义与黄金来源一致。

第一版代码前缀换算虽然通过十例，但扩大到 Tab、保留字面空格、长标签、Unicode 标签和双层引用的二十例后，检出六处差异。脚注头行中物理 Tab 列受标签宽度影响，不能直接减去去缩进后的代码逻辑列；两个引用脚注仍发生代码围栏化，其他场景新段落前缀也有偏差。失败源码、诊断与日志继续保留。

## 最终来源计划

- 没有段落样本时，使用容器现有首块的解析器来源信息；语义计划仍只新增一个段落，原子节点与顺序保持。
- 围栏代码使用解析器确认的开围栏位置，前缀不包括围栏、信息字符串或正文。
- ROOT 缩进代码使用物理行开始，不把代码缩进带到新段落。
- QUOTE 缩进代码二分查找该行解析器确认的引用标记。新段落使用标记后一个空格，原共享 Tab 和字面代码保持原字节。
- FOOTNOTE 使用解析器确认的代码缩进之前的原始续行前缀。脚注首行标记与祖先引用/列表仍通过已有统一前缀写入器处理。
- 候选保留全文重解析、所有节点/属性/marks/资源投影、不可编辑定义原拼写证明和失败原子性；不忽略 TIGHT 属性，不放宽来源断言。

无末尾换行的单行缩进代码没有本地 EOL 可借用，新边界按现有策略使用 LF；此前脚注头行的 CRLF/CR 保持原字节。围栏代码有开围栏行结束，使用该本地 EOL。永久黄金独立声明这两种策略。
