### 代码定界符与边界空格

在快捷、折叠、完整引用和直接链接内的代码片段，替换文本包含与现有定界符冲突的反引号时，两个公开文本 API 均返回不可表达错误。嵌套格式场景相同。完整替换为带首尾空格的代码文本也被拒绝。

六个场景、两个 API，在普通和哈希碰撞配置各确认 12 次拒绝。独立源码黄金先通过完整解析，验证其逻辑代码文本确实是调用方期望的字符串；失败后的源码、语义、保存点、历史、重复提交及零泄漏全部核对。证据为 `build/source-document-reference-text-20261006/linked-code-boundary-diagnostic-v5-proof.json`。

后续在既有统一来源计划中处理代码定界符宽度、必要的边界填充和引用使用后缀。保留代码内容中未编辑的原始拼写，不能靠整个段落重写来掩盖实体、标题或定义来源损失。最终仍须完整重解析与完整期望语义比较、原子发布和共同历史。

### GFM 表格代码中的转义竖线

GFM 表格的内联代码应把转义的竖线显示为竖线。官方 [GFM 示例 200](https://github.github.com/gfm/#example-200) 给出了代码和粗体中的这种行为。

当前 GFM 和 Extended 两种方言均把表格代码的 `a\|b` 解析为含反斜杠的逻辑代码文本，而期望值为 `a|b`。独立诊断包含普通代码、链接代码及官方示例的最小代码片段；两个配置各确认六个规范差异。表格外代码保留反斜杠、普通表格文字去除转义反斜杠的四个对照检查通过。原始源码、完整重解析及零泄漏核对通过，说明完整重解析自身也不能发现这个规范错误。

证据为 `build/source-document-reference-text-20261006/gfm-code-pipe-diagnostic-v1-proof.json`。诊断控制器退出 0 表示完成预期失败取证；两个配置的产品诊断运行均退出 1，不是规范验收通过。

后续核对解析器回调、代码文字规范化和原始范围绑定，在真实表格上下文中去除转义反斜杠；表格外代码的反斜杠语义必须保留。同步验证字符位置、来源索引、表格结构和编辑往返，不能只修改绘制结果。

### 转义括号后的 HTML 片段一致性

输入 `X]Y[` 后，两个 API 的实际源码和完整逻辑语义正确。但当前编辑结果把链接文本保存为一个 Text 节点，完整源码重解析产生五个同格式 Text 片段。HTML 导出因此分别产生一个和五个相邻链接元素，严格 HTML 一致性检查失败。

实际树、独立期望树、实际源码重解析树和两份 HTML 均保存在 `literal-bracket-trace-v2.log`；两个 API 的实际运行均完成。当前证据未证明来源索引错误，也未证明原生绘制不同。后续检查同格式片段、HTML 连续链接及来源位置的一致性，不删除或放宽现有断言来取得通过。
