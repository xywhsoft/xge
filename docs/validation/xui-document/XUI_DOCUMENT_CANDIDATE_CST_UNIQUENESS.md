## 已确认的问题

对 `[a][b][c][d][e][f]`，原有公开引用候选列表已经排序去重，保留五个标签 `[b]` 至 `[f]`。同一解析器会重复通知最后一个候选；CST 采集器直接追加两次，所以公开正文来源索引中 `[f]` 的语法归属和标签绑定各有两份。这个问题不能用完整重解析差分发现，因为完整与增量解析都重复采集。

新增独立公开回归核对全部五个候选的原始标签/外层范围，并要求每个候选只有一个行内语法归属和一个标签绑定。Linux ASan/UBSan 库和完整正常 Windows DLL 均编译成功、运行退出 1，明确报告最后一个候选 `public-inline=2 public-label=2`；没有 sanitizer 错误，失败前已释放所有对象。精确证据保存在 `build/source-body-index-20261006/failed-candidate-uniqueness-v4.json`。

此前正文来源索引的专项、官方语料、正常 DLL 和两平台常规入口验收仍是限定范围内的真实通过证据，不能替代这条新增唯一性要求。因此该候选暂不合入。

目录属于解析工作内存，定义作用域重新开始/结束时重置；普通与隐藏定义目录都在成功或失败后的解析清理中释放。目录容量受独立语法预算约束，仍通过 Document 分配器和取消状态处理。
