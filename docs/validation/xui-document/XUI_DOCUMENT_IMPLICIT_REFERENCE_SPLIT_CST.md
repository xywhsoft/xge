## 问题和最终行为

对 `[abcd]` 或 `[abcd][]` 插入段落换行时，显示标签变化后仍须绑定原引用定义。原实现回退为直接链接，会重新拼写其他格式、实体、列表符号和标题引号；多行显示标签还可能返回不可表达错误。

现在由同一解析器确认的行内包裹链和定义序号产生源补丁，把两个存留片段改为显式引用，例如 `[ab][abcd]` 与 `[cd][abcd]`。原引用定义、重复定义优先级、未编辑的实体、列表标记和标题引号保留。多行或含 Unicode 空白的定义标签从同一不可变 Document 的值缓存读取，按固定解析器的空白规则规整，并核对标签等价；不新增解析器或第二套文档模型。

原后缀补丁先于内容补丁执行，保留原坐标；发布前仍检查完整重解析与期望语义，两者和历史都属于根事务。

扩展矩阵还发现共享 `SplitBlock` 在格式换行节点之前创建默认输入 Text 的问题。新增输入 Text 继承 SoftBreak/HardBreak 的普通格式、资源和标题字段，因此 Rich 和 Markdown 在同一内核中保留输入格式。Text 不设置仅供 Image 使用的 `sLinkTarget/sLinkTitle`，原 schema 校验保持。
