## 实现

候选继续使用同一 Document 事务、来源存储、CST 和 Markdown 解析器，允许同节点的规范化文字/间隙范围进入来源计划。完整删除文字时使用解析器确认的归属范围移除独占格式标记；代码内部保留字面替换内容。段首删除后，仅将经来源映射确认且确实被解析裁剪的一个 ASCII 空格保护为 `&#32;`。每个补丁重新解析，继续证明完整语义投影和受保护定义；失败不发布私有候选。

换行路径修复了两个问题：无来源边界的表格段落把内部“不支持”交回统一语义序列化，由该路径判断 Markdown profile 的“不可表示”；首行容器前缀扫描排除经原字节确认的文件 BOM，避免有效引用/列表误走整段重写。没有增加第二套模型、解析器或旧 API 包装。
