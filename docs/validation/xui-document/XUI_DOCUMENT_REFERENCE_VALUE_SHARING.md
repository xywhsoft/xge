# Document 定义值与语义文本的持久字节共享

日期：2026-10-04。范围：K2/K4/K3。正式源码、实际 DLL、Linux 与浏览器完整批次验收通过；整体目标保持进行中。

原实现只共享完整相等的定义值，每条值是连续 Blob。在所属脚注内取消列表前缀时，仅少量标记改变，1 MiB 正文却产生 1,056,551 字节历史独占。缓存初版候选修复后，另一个独立探针发现，已使用脚注的 SOURCE 编辑仍复制语义文本：1 MiB 正文首字修改产生 1,052,981 字节历史独占。两条问题分别有实际失败记录，不能互相替代。

## 实现

每个有序定义项持有不可变字节序列，共用 Document 的持久序列存储。克隆、释放、普通内存核算、异步发布计划均遍历此所有权。保留每条定义的类型与完整编码，未使用及重复定义仍按有序记录核对。

共同字节共享算法先证明前后缀，再使用滚动哈希定位中间候选；所有保留区间逐字节比较，哈希碰撞不能改变内容。新差异段拥有紧凑 Blob，避免保留整条新解析值。源码重新解析后，定义缓存和已匹配身份的语义文本都使用这套算法；事务、Snapshot 和 Undo/Redo 不另建历史。

按每个 Blob 的全部切片累计覆盖度。对至少 4 KiB、当前覆盖不足四分之一的 Blob，复制剩余小片段，避免一个头部或几十字节正文把已删除的大正文继续计入 Current。多个修改间隔共同保留的大正文不因单片短而被整体复制。

异步与同步路径的持久树可能有不同节点布局。验证因此使用独立的可达分配集合，逐项精确核对 Current、History、Snapshot 和 Other 字节及所有者；同时核对同步/异步内容、历史、分组、限额和发布行为。原来两个独立树的物理字节完全相等不是正确的记账依据，原失败记录保留。
