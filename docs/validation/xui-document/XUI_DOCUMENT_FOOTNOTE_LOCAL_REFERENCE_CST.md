## 问题与实现

原解析器在全局引用表建成后才解析脚注正文，而且禁止脚注正文消费链接定义。结果是正文里的快捷、折叠或完整引用可能被投影为普通文字；隐藏脚注中的定义也不能激活外部引用。直接放开消费会在查找表构建之后添加定义，既破坏顺序，也可能使内部指针失效。

现在脚注声明到达其物理位置时，复用同一正文块解析函数预采集普通链接定义。在全局查找表建立之前完成这一过程，因此可见、隐藏、重复脚注与根定义共同按物理顺序决定第一个有效定义。预采集使用临时块状态，不发布正文语义节点。

实际脚注正文解析时重放已确认定义的来源回调，不再新增定义或地址/标题值。Document 的内部阶段回调区分预采集与重放：前者填充统一定义缓存及定义 CST，后者在真实脚注范围发出正文来源记录并核对缓存。按原始范围二分查找缓存，允许脚注声明与首行链接定义共享物理起点。

临时 MD4C 上下文使用现有 Document 分配器、取消机制及块语法；失败时回收临时数组并交还引用表所有权。没有新增公共 API、兼容包装、第二份 Document 模型或独立语义历史。块代码、HTML 内伪定义保持不生效；脚注内的嵌套脚注声明仍按原保留字面语法处理，本批不宣称支持递归脚注定义。

## 原失败与验收边界

故障驱动最初误要求失败的 PrepareRun 重复返回原错误，继而误将 ContinueSource 的重试约定理解为直接再执行 Run。原失败与输入保留。公开 API 和状态机明确：Run 只执行 QUEUED 输入一次；失败结果通过 GetInfo 查询，未取消输入通过 ContinueSource 新建候选重试。最终检查保留原错误、单次执行、取消拒绝、重试、发布原子性和历史断言，没有为错误测试修改产品。

代码边界父批 v6 的正常 DLL 69 条及 Core 96 条实际退出 0，Windows 常规入口因 HTML 故障测试的有符号/无符号比较编译失败，控制器退出 1；Linux 与分析未启动。最终脚注 v4 只把有界失败计数转换为 long，保留全部故障断言，Windows 和两种 Linux 配置专项通过。父失败不能当作完整父批验收，也不能继续表述为运行中。

脚注 v4 的完整 Native 在第 55 条 Core 检查失败：旧用例只计一个外层脚注定义，并期待 `/raw` 出现在可见正文，且源码黄金会删除链接定义。独立普通/碰撞诊断确认定义数应为二、URI 应是链接元数据，跨段替换仍保留原定义字节与 URI/title。最终 v5 更新该旧用例并加入 12 个明确的跨定义源码黄金；没有为了旧预期恢复错误产品行为。原 54 条通过、失败和输入均保留。v5 后续完整重验又在未使用定义的旧可见文字断言失败；v6 修正后实际 DLL 整个 Core 已通过，完整候选尚未验收。

本批尚未证明完整 CST、所有结构命令、全量增量性能、真实 IME/读屏或平台 UI 矩阵。Document 私有公式/Mermaid/HTML 渲染继续保留；其他四平台通用 WebView 及公开通信仍按用户决定暂缓。
