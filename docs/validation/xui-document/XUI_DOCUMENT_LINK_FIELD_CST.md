# 链接、图片字段 CST 与图片字段级无损编辑

日期：2026-10-05。所属 K2/E1。194项正式输入、实际DLL、Windows/Linux与Web本批正式验收通过。保持原整体重构目标；本报告不是完整 CST 或编辑器完成声明。

## 内核实现

沿用统一 Document 的 `xui_doc_inline_syntax_t`，增加 `DESTINATION` 和 `TITLE` 两种语法子项。父项为行内链接或图片：Source 范围包含字段的 `<...>`、引号或括号，Content 范围为未经解码的字段值。标签中的嵌套格式仍处于父项的 Content 内，字段子项则位于其后缀中。原结构布局、284 个公开函数、ABI16 和原生格式7没有改变。

范围由 md4c 接受链接语法时记录，经已解析的 dummy mark 传递，在父 span 关闭前发布到 Document CST。显式空标题与没有标题分别处理；遗漏空目标的零宽范围位于闭合 `)` 前。多行标题保留原始 CR/LF、容器前缀及分隔符范围，不从合并后的标题字符串推测来源。无 XUI hook 编译保持原 parser 类型与路径；启用 hook 的临时 mark 增加两个 OFF，分配仍经过 Document 的预算、失败与取消管理。

引用形式继续由父项的 `iDefinitionIndex` 指向隐藏定义，不在使用位置虚构字段子项；自动链接没有显式后缀字段。既有持久 CST 序列和增量 graft 统一处理新子项的来源位移、父索引和快照生命周期。

## 图片命令

alt、格式和包围链接未改变时：

- 只改 URI：只替换目标 token，原标题、引号、空白、行结束保持。
- 只改标题：只替换或删除标题 token；原目标和分隔空白保持。无标题时在目标后插入；遗漏空目标先写入 `<>`。
- 同时修改：保留两个字段之间的原始 SourceStore 字节，分别修改字段；不复制原始 alt。
- 引用图片：保持 alt 和隐藏定义，将使用位置转换为明确行内目标。
- 无变化：保留原字节、revision、历史和保存点。

新测试还确认了旧验证器拒绝合法多行 Markdown 标题的问题。Markdown 图片命令现在允许标题和包围链接标题的 CR/LF；资源地址仍拒绝换行。标题写入器在共有 Markdown 序列化路径将 CR/LF 写成 `&#13;`/`&#10;`，避免插入块边界或丢失容器前缀，并保留请求的语义字符。Rich 图片命令原有标题限制未扩大。

候选在私有事务内构造补丁，完整重解析并核对期望语义后才接受；身份、发布、历史和回滚共用 Document 内核。
