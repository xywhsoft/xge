## 已确认的问题

1. 从任务项移出唯一段落后，语义意图保留了任务属性，却没有保留空段落。源码重新加载会生成空段落，因此当前结构与加载后的结构、HTML 输出不同。
2. `>\t  code` 的 Tab 同时承担引用可选空格与代码缩进。物理字节边界不能表示 Tab 内的逻辑列；移动时丢掉代码列会触发整体序列化。
3. `> \t  code` 等输入的代码缩进内仍有 Tab。去掉引用后，Tab 的停靠列改变，即使没有跨越祖先边界的 Tab，也可能触发整体序列化。
4. 脚注正文会在去缩进后的输入上解析。原文件的物理列与解析器列不是同一坐标系，不能用原物理列推测解析器边界。

原始失败及其输入保留在 `build/source-document-footnote-local-reference-20261006` 的 v228、v236、v238 记录中。v236 有一个无效期望：脚注定义之后的缩进代码仍属于脚注正文。v237 只把该代码移到定义之前，并增加移动前后代码文本必须一致的独立检查；其余八个期望不变，原失败未覆盖。

## 实现

任务项的空段落由已确认的候选解析结果证明，在私有语义计划中分配新 NodeId 并记录 INSERT，与 MOVE 同一事务发布。只允许编辑后为空的任务项生成该段落；任务属性、旧 NodeId、其他定义与完整语义证明保持原有保护。失败或取消不发布中间状态；Undo 恢复原段落，Redo 恢复同一新空段落身份。

缩进边界以解析器记录的引用标记、列表首标记和最外层续行作为字节/逻辑列锚点。到达脚注时停止使用外层坐标。转换边界时校验实际扫描终列与解析器终列一致；在 Tab 内分割时，仅把右侧的虚拟列写成空格。

代码移动根据目标容器前缀占用的代码列调整四列缩进。Tab 相位不变且无额外容器列时保留原拼写；需要调整时只重写已确认的代码缩进，内容边界之后的源码、额外缩进、行尾和未编辑区域继续共享原 SourceStore 片段。发布仍要求完整重解析、语义投影及未编辑定义拼写校验；没有放宽比较器或通过导出器掩盖结构问题。

主要实现位于候选 v241 的 `src/xui/document/xui_document_markdown_edit.c`。v239 的单成员工作归档用于快速诊断，不代替全新构建。
