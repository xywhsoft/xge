# Document 跨 item 整词字体回退

更新：2026-10-02。通用 WebView 继续只实现 Windows 基础网页承载，其他平台预留；Document 内部公式、Mermaid、HTML 的脚本、测量和截图通道保留。本项属于统一 Document 原生文本内核的正确性工作。

## 问题与修复

上一批 DLL 的独立公开探针已经复现：主字体缺少 `i`，fallback 覆盖完整 `ffi`，但对首个 `f` 塑形并传入完整 `ffi` 上下文时，仍选择部分主字体。不同样式把同一个词拆为 item 后，字体选择单元被错误地限制在 item 内。

现在字体覆盖探测使用完整上下文中的字素和词段，输出整形仍只接受当前 item。先定位包含当前字节的完整 Unicode 17 字素，再向两侧扩展兼容脚本的词段；沿原有有序字体链，选择既覆盖完整词段、又能覆盖当前请求片段的首个字体。所有输出 glyph、cluster 和 caret 仍相对当前 item，不会把邻接 item 的 glyph 输出或重复绘制。

第二次片段覆盖检查是必需的：某字体可以借 NFC 或 GSUB 渲染整个组合字素，却无法独立渲染调用方请求的组合标记片段。仅凭整词覆盖选择它，会产生 `.notdef`。如果没有字体覆盖完整词，继续既有的局部字素与码点回退，不把普通部分覆盖当成错误。

词段沿用现有选择器的字母、标记、数字和默认可忽略字符规则。空白、标点、必需换行及 SHY 分隔选择单元；不同已解析强脚本分隔词段。显式脚本覆盖与完整 item 的既有策略一致。Script_Extensions 已由段落脚本图解析，不再在字体选择时覆盖其结果。这里没有宣称实现完整 UAX #29 语言学词分割。

## 所有权与失败行为

完整 item 复用自己的字素图；具有 fallback 链的上下文子 item 才按需建立完整上下文字素图。脚本图、item 字素图和新增上下文字素图都只属于同步整形过程，发布结果前释放；最终行载荷保留 glyph、caret 和实际字体的所有权。成功结果不借用调用方的 item/context 字节。

任何新增分配失败返回 `OUT_OF_MEMORY`，走同一 glyph run 清理路径。单次调用内缓存词段边界和选定字体；全词无法覆盖的判定也缓存，保留现有不匹配长词的线性逐字素回退。不同调用间尚未建立共享字体覆盖缓存，长段落被切成很多样式 item 的总体性能仍要继续验收。

## 验证边界

新增两份确定性的项目自有字体，部分主字体的 `f/x` advance 和轮廓与完整字体不同。公开 API 检查首/中/尾 item、复制且无 NUL 的输入、两种方向、词/脚本边界、显式脚本、NFC 组合与片段，以及释放调用方后的字体生命周期。Document 原生专项以字面 PUA glyph 绘制独立参照，核对 Rich、Markdown、跨字体/字号、六种缓存/基础范围/仅 drawText/无 paint 路径的完整 RGBA、caret/hit、重排、字体失效及 Document 释放后的 Snapshot。

已有阿拉伯长上下文回归保持全部独立 HB 整段 glyph/GPOS 对照。medial-only 测试字体不覆盖词的 init/fina 时，应优先选择完整字体；未映射 acute 使完整词无法覆盖时，仍验证局部 medial 回退。实际 C 覆盖入口另外直接检查 512 个标记后的 medial 覆盖，避免整词策略遮蔽原来的 joining 回归。

最终日志、真实退出码、源码/字体/DLL 指纹和失败记录使用独立前缀 `artifacts/xui-document-rebuild/validation-2026-10-02-word-context-`。旧 ASCII 批次的失败探针和封存清单不重写。

字体选择一致不等于把不同字体的整段放入共同 glyph buffer；跨字体任意 GSUB 前后向替换仍未完成。完整控制/行边界、CST/结构命令、复杂导航、性能与真实平台验收等整体设计剩余项继续，长期目标保持进行中。
