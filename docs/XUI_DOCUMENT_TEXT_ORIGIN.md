# 文字归一化来源与 NUL 替换

日期：2026-10-05。所属 K2/K4。本批已正式合入，实际 DLL 与完整回归验证进行中；整体重构目标 active，未完成。

## 问题与独立证据

实际旧 DLL 的 90 场景探针发现 72 个来源范围错误和 9 个代码块语义不一致：行内代码换行变为空格后没有原始范围，代码块空行范围包含引用或缩进前缀，Tab 展开的空格和 NUL 替换也没有来源。代码块字节诊断确认 NUL 被替换为 U+FFFD 后，原始零字节又随下一段直接文字输出。

独立无 XUI hook 的 MD4C 检查进一步发现行内代码会绕过 NUL 替换。v3 的常规/Core/既有专项、sanitizer、分析和语料虽然通过，该独立运行仍退出 1，因此 v3 未被接受。旧驱动、编译输入、失败日志和随后 v4 输入均保留。最初探针和诊断驱动还出现过 C 字符串十六进制转义及 main 宏重定义的编译错误；这些是准备失败，不是生产运行证据。

精确最终 v5 驱动、头文件和构建输入另行归档，并在当前图片 alt 正式 DLL 上编译及运行；编译退出 0、运行退出 1，确认差距仍在实际交付 DLL 中。

## 实现

解析器通过内部文字来源回调，在归一化文字回调前提供原始范围、回调类型、内容类型和回调字节数。Document 按次消费并核对类型、大小及边界，将语义文字和来源片段一起写入唯一的树、快照和历史。

- 行内代码和公式的换行空格、行内 HTML 换行、代码及 HTML 块行尾使用解析器已确认的原始行结束；EOF 补齐的换行使用零宽原始范围。
- 代码和 HTML 的缩进采用解析器实际使用的容器逻辑列。保留下来的普通空格具有直接来源；Tab 展开的剩余空格映射到该 Tab 原字节，不包含引用、列表或围栏缩进前缀。普通空格回调继续采用最多 16 字节的分段。
- NUL 只替换一次。受保护的代码、公式和 HTML 行内文字也经过替换路径；替换片段映射回单个原始零字节，保留 HTML 内容类型。原始源码中的 NUL 不被修改。
- 移除从之前文字游标扫描代码换行的旧路径、已失去用途的代码正文起点字段及其扫描。内部回调继续按 TLS 保存和恢复，兼顾独立解析器及嵌套调用；长文字扫描检查取消状态。

不新增公共函数、公共结构布局或原生文件版本，不建立第二份内容及历史。
