# API 3 hosted runtime identity

`--host-xrt` API 3 builds use `xge3_host.dll` / `libxge3_host.so` and the
matching `xge3_host.lib` on Windows. Debug builds use `xge3_hostdbg`.
Embedded builds, including the IDE profile, keep `xge.dll` / `libxge.so`
and `xgedbg` names. Renaming a previously linked PE file is insufficient:
its export image name still controls the import name generated by GCC.

The normal builder records `runtime_image`, `unstripped_image`,
`import_library` (null on ELF), and `runtime_soname` (null on Windows).
Consumers must use those names instead of inferring a filename from a
profile. ELF builds carry their basename as SONAME, so a client linked
using an absolute library path records the basename in DT_NEEDED.

Artifact naming does not enter the public ABI fingerprint or compiler
configuration. It changes the loader identity and import library, not
the native API or object code. No runtime forwarding layer is added.

## Strict qualification reuse

For a separate source tree containing the exact qualified production and
ABI inputs, use:

```
python tools/build/build.py default <new-output> --host-xrt \
    --relink-from <qualified-output> --relink-source <qualified-source>
```

The old source path is explicit because historical dependency files use
relative paths. The builder checks compiler identity, compile flags (only
the generated host-header directory may move), profile, selected sources,
features, public ABI configuration, original cache keys and dependency
stamps, and byte equality of every old/current dependency. It references
the original objects directly, including the exact shared HarfBuzz object
and Windows resource. There is no compile fallback. The original source,
objects, cache records and reports are never written.

The report's `qualified_object_build` records the original report hash,
each object's and dependency file's hash, all dependency content hashes,
and final input-stability checks. The new normal link derives host imports
from the reused objects and generates its slots using the existing builder.
Only a matched new runtime, import library and metadata may be delivered;
the old qualified image remains a historical artifact.

`tools/test/check_host_image_names.py` checks naming, strict-reuse rejection
cases, real PE export/IAT or ELF SONAME/NEEDED, unchanged exports, and a GCC
CPU-only loader collision with embedded and host fake libraries. It does
not run TinyCC PE files, initialize an engine, create a window, or access
the actual clipboard.
