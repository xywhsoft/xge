## 问题与统一实现

父版本虽然已经支持直接删除行内叶节点，但按 Paragraph/Heading 的 GAP 选区删除仍可能重写整个引用块，产生额外空引用行。空 alt 图片有零宽内容范围，引用内换行还有下一行容器前缀，单靠文字字节选区无法覆盖。

现在同一私有 `doc_markdown_inline_delete_source_patch` 同时接受节点命令和范围编辑的反序连续 Delete 操作。仅接受同一 Paragraph/Heading 内无子项的连续节点；原始范围来自同一解析器的行内来源记录，唯一内容归属查找排除 URI 和标题字段，完整占用的格式包装一并删除。空 alt 图片允许零宽内容但必须有非空对象来源，纯字面零宽范围不会误删。

连续范围使用首尾解析归属，并确认覆盖整个范围的格式包装。删除 SoftBreak/HardBreak 时，只在到下一行内归属之间的原字节全部为已允许的容器续行空白时合并物理行；引用标记只有存在真实 Quote 祖先才可消费。未识别的语法回退原处理路径。段首暴露的一个 ASCII 空格沿用最小 `&#32;` 边界修复，并重新证明整篇语义。

所有计划仍在同一 Document 私有事务中完整重解析，证明正文及保留脚注投影、受保护定义原字节，再通过统一根事务、稳定身份、位置映射和历史发布。没有第二个文档模型、解析器或旧 API 包装。当前仍有行内语法扫描和全文验证，不证明 K4 的次线性增量目标。
