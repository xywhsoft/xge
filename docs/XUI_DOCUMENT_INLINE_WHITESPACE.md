# 受保护行内内容的多行空白

日期：2026-10-05。所属 K2/K4。隔离候选 v3 通过专项，正式源码尚未合入；统一 Document 和原 13 个工作包的整体目标仍为 active。

## 已确认的问题

当前实际 v6 DLL 和没有 XUI hook 的解析器都丢失受保护内容在下一行的前导空白。例如，源码 `z <i title="a\n b">` 的 HTML 对象变成 `<i title="a\nb">`；行内代码 `aa\n bb` 变成一个空格分隔的 `aa bb`。引用和列表内也有同样问题。

修正后的独立 v2 驱动在两条路径均编译退出 0、运行退出 1，13 个场景全部失败，包含标签、注释、处理指令、CDATA、声明、代码、Tab 和容器。首次驱动没有安装空的 block/span 回调，并错误地收集代码节点；这些准备错误及日志已归档，失败结论不依据首次驱动。

代码内容的内部空白应保留，行结束转换为空格；只在首尾均为空格且内容不全为空格时，各裁剪一个空格。HTML 属性等受保护内容也必须保留其内部字符。规则依据 [CommonMark 代码](https://spec.commonmark.org/0.31.2/#code-spans)及 [原始 HTML](https://spec.commonmark.org/0.31.2/#raw-html)。

## 候选实现

行分析保留解析器已经接受的容器缩进与剩余内容边界。普通行记录去除容器前缀后的原始起点，以及一个被容器边界分割的 Tab 所剩列数。继续处理 HTML、代码或公式时，输出内容空白；普通段落仍使用其正常的缩进规则。

完整空格和 Tab 使用直接来源；被容器分割的 Tab 产生剩余空格并映射回单个原始 Tab。代码起止裁剪使用内容的真实边界和物理行尾，保留内部空白；如果最后一个被裁剪字符来自分割 Tab，只消费一个剩余空格。临时表格行、脚注行和常规行都初始化新元数据；扫描继续检查取消状态。

一切进入已有语义树、来源片段、事务、快照和历史，不增加公共 API、公共布局或原生格式版本。原生 Markdown 重载继续从保存的原始源码构建解释。

候选 v1 的扩展黄金发现代码开头“空格加换行”仍丢字节，未获接受。该版本的 188 项原字节输入和失败日志保留；v2 修正物理行尾后通过基础检查，v3 再加入完整失败和取消扫点。

## 实际验证

- 2,304 个独立语义、原字节及位置黄金：32 种内容、三种行结束、三方言、原生重载、SOURCE、Prepare、READY Continue、Undo/Redo 和释放 Document 后快照。
- 6,608 个逐字节边界差分，6,401 次增量执行：删除、Tab、定界符及二进制 NUL；核对全文语义、来源、语法和历史。
- 1,568 个 SOURCE/Prepare 内存失败点与 748 个 Prepare 取消点：内容、身份、revision、保存状态和历史原子保持，分配无泄漏。
- 96 个无 XUI hook 场景核对三种行结束、代码首尾裁剪、分割 Tab、HTML 和 NUL。
- 完整 Core、文字归一化、图片 alt、普通及强制哈希碰撞 ASan/UBSan、修改模块静态分析及 652 项语料解析/来源/原生往返/差分。

共 21 条全新检查命令实际退出 0。190 项验证输入归档；最终候选为 188 项输入、6 项拟合入，包括两个共同套件入口和新 bat。这三个运行入口尚未正式执行，不计为已通过。

精确最终驱动和 188 项输入另行归档，在当前正式 v6 DLL 编译退出 0、运行退出 1；当前正式 186 项输入保持不变。

另用保留的 `md4c-html.c` 比较语料期望 HTML。Windows 标准流改成二进制后，修复前后均有相同的 54 项字节差异，包含列表输出换行和转义方式；完整失败记录一致，没有新增字节差异。该检查不能认定完整期望 HTML 一致，也不将这些字节差异全部认定为解析缺陷。它不属于上述 21 条通过命令。第一次使用文本标准流的结果属于准备差异，不能用于语义结论。
