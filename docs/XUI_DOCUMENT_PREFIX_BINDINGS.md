日期：2026-10-05。所属 K2/K4，保持原 13 包和统一 Document 内核目标。修复已与来源索引工作内存优化联合正式合入；父 202 项批次已验收结束，当前 207 项输入保持原样，Windows/Linux Core 正式验收失败，修复与重新验收待完成。

## 问题与结果

正式 DLL 的来源索引中，`  > text` 和 `  - text` 的两个前导空格只有容器范围归属，缩进绑定从标记开始。原始字节没有丢失，但无法从绑定查询精确识别这些字节属于哪个容器缩进。

候选由解析器直接提供已经接受的缩进原字节起点，引用和列表首行绑定覆盖该起点至原前缀结束。标记范围仍单独保留。对同一个 Tab，父子容器可以保留重叠的原字节范围，并分别报告自己的逻辑列。脚注使用实际去缩进输入的起点，不能把定义标签、冒号空白或已经移除的四列前缀重新归给正文容器。

首行引用前缀继续保留解析器既有的空白消费；不会仅凭物理行空白重新分配给子列表。续行的部分 Tab 消费按实际解析路径记录。

## 实现

- MD4C 的受保护来源回调新增原缩进起点：引用记录七个值，列表记录六个值。只在已接受的空白前缀内定位逻辑起点，不再识别另一套语法，不拷贝源码或扫描整行正文。
- Document 收集器核对范围和前导空白，使用现有分配器、取消与失败清理路径保存不可变派生元数据。
- 引用相对记录为 28 字节；列表首行记录为 24 字节。普通列表续行继续保留原来的 20 字节记录，避免逐行重复保存一个相同偏移。
- SourceIndex 收集和绑定解码共用这些确认起点。同一快照、同一 SourceStore，没有第二个可写 Document 或另一份历史。
- 取消列表命令读取首行已有标记/逻辑列字段，并核对扩展后的首行记录大小。公开 ABI 和接口布局保持；原生 Markdown 加载从保留源码重建这些元数据，文件格式仍为 schema 7。
