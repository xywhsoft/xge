## 问题与实现

在 `- > + > abcd` 或 `- > 7) [x] abcd` 中插入段落换行时，原来源计划只处理第一个列表开头，剩余标记使它退回整块序列化，增加多余空行。`baseline-v1-proof.json` 的普通/碰撞配置均实际编译 0、运行预期 1；两个独立最小源码黄金都不符，但完整语义、光标、重解析和 Undo/Redo 检查通过，退出前完成释放。

新候选仍使用同一 Document 事务、CST 和 Markdown 解析器。多层列表复用现有段落写入器的解析器确认前缀：各列表开头转换为正确续行缩进，任务标记仅保留在首行，引用和 Tab 按原始逻辑列处理。不能完整确认前缀时保留原回退；每个来源补丁仍需完整私有重解析和语义、定义核对。没有引入第二个文档模型或 Markdown 扫描器。

单模块产品变化位于 `build/source-document-container-prefix-20261006/snapshot-v7/src/xui_document_markdown_edit.c`。父输入是已验收、不可变的行内边界 `snapshot-v9`；当前候选 255 项输入，产品与 v2 相同，主工作区源码保持冻结。
