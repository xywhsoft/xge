# 取消列表的结果选区、松散列表语义与跨空列表边界

日期：2026-10-04。范围：整体重构设计 K2/E1。正式 Core、实际 DLL、Linux 与浏览器完整批次验收通过；整体目标未完成。

## 已确认的问题

上一批 Windows 完整套件在实际 DLL Editor 中失败：取消列表成功，读取选区成功，但再次设置选区返回 -2。独立 DLL 追踪定位到以代码块为第一个子块的列表项 GAP；原命令把两个端点都映射到第一个子块的 GAP 0。代码块是承载文本的节点，这个位置无效，也丢失了原选区末端。

跨列表路径还有同类内部边界丢失。新增独立复现使用上一批正式源码编译成功、运行退出 1；对应旧正式 DLL SHA256 为 `9cb65b0f21a14aad547d38a6a7be73bde7707a75f9f4e166cec37705b9c54cdc`。同一扩展维护测试链接该 DLL 也实际退出 1。原始失败记录保留，未覆盖。

删除唯一包含块间空行的列表项后，保留的前、后列表可以重新变为紧凑列表；原命令仍保留旧松散属性，导致正确来源候选无法通过完整语义核对。跨空项选区还会使来自不同原列表的同种标记重新相邻，原正式源码对此原子拒绝。

## 正式实现

- 同一列表中的 Item GAP 按提升后的父容器边界计算，保留原子块间位置；仅计算实际保留的子块，扣除删除的头列表包装。Rich 和 Markdown 使用同一命令实现，保留两端 affinity 和正反方向。
- 跨列表在移动前记录端点两侧的稳定子块 ID，全部操作结束后按最终父容器定位内部边界。原父容器 GAP 仍按整组选区处理。
- Markdown 候选完整解析后，只为本次操作影响的原列表祖先或新后缀包装更新派生的 TIGHT 位；新后缀必须由原列表中未改动的子项组成。其他属性、全部正文和整篇语义仍严格核对。Rich 不执行这项 Markdown 派生属性归一化。
- 跨空列表按最终相邻包装判断分隔，必要时只修改后一个列表所属的 bullet 或 ordered delimiter。正文、任务标记、未操作项及定义原字节保持。
- 已添加的边界空行不重复添加。空项原有父引用/列表/脚注前缀与换行仍保留；隐藏定义正文不能误判为纯空白。
- 来源复制证明、完整重解析、全部有序定义核对、所属脚注正文例外和原子发布继续使用统一内核。无新增公共函数或旧 API 兼容包装。
