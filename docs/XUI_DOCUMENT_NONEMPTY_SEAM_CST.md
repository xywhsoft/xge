# 非空跨块替换的来源保真

本项属于整体重构的 K2/E1/K4 正确性工作。富文本与 Markdown 继续共用 Document、事务、快照、位置映射和历史；没有增加第二个内容模型或旧 API 包装。

## 已确认的问题与实现

此前标题合并候选的实际 Windows DLL 在 48 个非空跨块替换对照中，语义、撤销和快照仍成立，但未编辑的实体、格式或标题拼写被规范化。初版隔离修复通过 6,912 个扩展对照后，进一步发现 CODE 中输入连续反引号的 16 个来源差异。两类原失败、源文件和日志都保留。

隔离修正版使用同一写入器中的解析器来源记录：

1. 在左块末端 TEXT 到右块首个 TEXT 的精确边界，先保存左侧格式包裹内部的输入位置。
2. 删除格式包裹外的块分隔及右侧标题结构；新文字单独写入左侧原格式内部。已有实体、链接引用和格式拼写保留。
3. ATX 结束标记、Setext 下划线与最终换行继续采用已验证的标题后缀计划；隐藏定义间隙按既有规则移动。
4. CODE 使用已有的解析器包裹计划，检查新内容的反引号长度与首尾空白。在必要时调整定界符和 padding；按原坐标从后向前应用结构删除、代码闭合符、输入和开放符。
5. 完整重解析，核对整树语义投影与定义保护，才进入同一个根事务和历史。分配失败、取消及拒绝不得产生部分发布。

例如在 `__keep__` 后跨块输入 `Z*[]`，新源码在原包裹内写成 `__keepZ\*\[\]__`，保留旁边的 `&amp;`、右侧原格式和标题拼写。CODE 输入连续两个反引号时，必要的定界符扩展由解析器确认的 CODE 范围承担。

上述新路径覆盖精确块边界上的单行非空替换；本批不证明任意多行输入、任意部分选区和全部结构命令已经完成。

## 编辑控件的输入规则与原失败记录

整体设计第 6.2/6.3 节规定源码输入和视觉语义输入不同。SOURCE/LIVE 编辑原始 Markdown；VISUAL 表达语义文字，由适配器转义。

最初 Editor 驱动把 LIVE 的原始输入错误地要求为 VISUAL 的转义语义，原控制器实际 1，保存在 `heading-replace-editor-v1-observation.json`。随后源码位置漏填 ROOT 身份，选区在输入前被拒绝，第二次失败保存在 `heading-replace-editor-v2-observation.json`。两次源文件、独立候选和失败日志均未修改。

最终驱动保留全部语义、caret、历史和快照检查，并扩展为 VISUAL 96 个语义黄金、SOURCE/LIVE 192 个原始字节黄金。原始字节预期由声明的选择范围与输入拼接，未取实际输出作为预期；三种模式都与完整解析核对，并继续切换三模式验证同一 Document 的内容和历史。旧 DLL 的 76 个差异只来自 VISUAL 来源策略；SOURCE/LIVE 原始输入对照成立。

该 Editor 使用实际 Windows DLL 和测试 surface/proxy、合成 TEXT 事件；不代表真实窗口、IME、读屏或字体/DPI 验收。
