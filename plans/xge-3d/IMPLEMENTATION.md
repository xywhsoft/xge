# XGE 轻量 3D 支持落地文档

版本 1。制定日期 2026-10-03。本文是长期开发任务的执行基线，任务已于同日启动。执行进度见 [PROGRESS.md](PROGRESS.md)。

目标是在保留 XGE 轻量定位的前提下，完成可裁剪的 3D 模型、场景、光照阴影、骨骼动作及必要的空间与资源支撑。优先用 C API 和可运行范例交付。沙盒游戏用于检验通用能力，游戏业务在独立项目实现。

## 1 开发范围与完成条件

本期必须完成：

- 2D、3D、ShapeEx、XUI 的编译裁剪，以及 XUI 每类公开控件的独立裁剪。文本、音频、SVG、粒子、内置资源和第三方依赖随使用情况裁剪。
- 真正的 GPU 三维变换、相机、深度渲染目标、模型共享实例、节点层级、拾取和天空盒。
- glTF 和 GLB 模型与基础材质；方向光、点光、聚光灯；太阳级联阴影和聚光灯阴影。
- 骨骼蒙皮、独立动作加载、基础混合、骨骼遮罩、事件、挂点和根运动输出；外部 FBX 与 BVH 动作转换、离线人形重定向。
- 可选静态 IBL、可选高度场；实例化、视锥裁剪、应用指定的 LOD、资源异步处理与上传预算、相对原点渲染、基础空间查询。
- 一套有限帧运行的综合范例、相关测试、体积与构建耗时记录，以及准确的公开 API 使用说明。

长期目标完成必须同时满足：P0 至 P6 的必需工作包均有实现和通过的证据；关闭功能后的源码、资源和依赖确实消失；综合范例使用公开 API；旧默认配置的相关能力没有本任务引入的回归；已实现能力和限制如实进入使用文档。静态 IBL、高度场属于必做但可关闭的扩展。库的功能完整性以本段为界，不随参考引擎功能列表扩张。

本期暂缓：点光源阴影、实时 GI、动态反射探针、体积雾、高级屏幕空间效果、实时通用重定向、Motion Matching、复杂动画图、完整场景编辑器、多 GPU 后端重写、完整物理引擎和导航系统。后两项提供通用数据接入说明和小型应用验证，不引入空接口冒充实现。

XGE 不包含：世界分块策略、程序化世界生成、生物群系、建造规则、物品与配方、背包、NPC 业务、沙盒存档、多人同步。区域加载和对象状态由应用决定；引擎提供模型、几何、资源、动画和渲染机制。

## 2 实现约束

1. 新增运行时代码和新增导入工具采用 C；新增依赖必须能按 C 编译。现有可选文本依赖的实际语言边界按现状记录，不能宣称整个历史仓库都已纯 C。
2. 优先复用 xrt 的 Array、Map、Pool、SlotMap、Buffer、文件、计时和线程设施。不要再次编写通用容器、任务框架、序列化框架或引用计数框架。向量、矩阵、GPU 顶点等固定布局可采用直接结构与连续数组。
3. 代码保持短、清晰且可检查。不要为减少行数压缩成难以阅读的一行，不增加只有一个实现和一个调用者的转发层。
4. 从现有 GL 3.3 路径开始，着色器与格式按 GLES 3.0 和 WebGL2 的基础能力设计；不先建设通用 RHI、渲染图或 ECS。真实平台测试结果分别记录。
5. 保留现有 2D 与 2.5D API 行为及公开结构布局；新增 3D 类型独立命名。公共入口继续放在 `xge.h`，XUI 宏和入口放在 `xui.h`。不要扩大应用对私有实现的依赖。
6. FBX、BVH 解析和动作重定向放在离线工具；运行库只消费 glTF、GLB 或经过明确验证的缓存。优先沿用标准格式，首版不新建二进制资源格式。
7. 用功能收益、Release 体积、编译时间和维护成本决定实现路线。运行库、工具、测试资源和示例资源分别统计，不能把离线工具依赖计入最小运行库，也不能隐去运行时动态依赖。
8. 当前工作区有大量其他工作的修改。开始实现时记录基线，不回滚、清理、覆盖或顺便重构无关文件。共享构建和公共头的改动必须小而可审核。

## 4 P0 先完成裁剪与快速构建

### 4.1 宏契约

新增统一配置入口，所有功能宏为数字 `0` 或 `1`，使用 `#if` 判断。以下名称是待实现的接口约定：

```c
XGE_ENABLE_2D
XGE_ENABLE_3D
XGE_ENABLE_SHAPE_EX
XGE_ENABLE_XUI
XGE_ENABLE_TEXT
XGE_ENABLE_AUDIO
XGE_ENABLE_SVG
XGE_ENABLE_PARTICLES
XGE_ENABLE_EMOJI
XGE_ENABLE_HARFBUZZ

XGE3D_ENABLE_MODEL
XGE3D_ENABLE_LIGHTING
XGE3D_ENABLE_SHADOW
XGE3D_ENABLE_ANIMATION
XGE3D_ENABLE_IBL
XGE3D_ENABLE_TERRAIN

XUI_ENABLE_BUTTON
XUI_ENABLE_TREE_VIEW
XUI_ENABLE_DOCUMENT
/* 每类公开控件均有对应开关，完整列表由 P0 清点生成。 */
```

共同的 GPU、纹理、缓冲、资源和基础绘制保留为必要底座，不随高层 2D API 一起误删。第一版 XUI 明确要求 2D 与文本；ShapeEx 要求 2D，SVG 要求 ShapeEx；阴影要求 3D 光照；动画要求模型模块。其他依赖依据实际引用补充，不通过启用全库消除链接错误。

配置文件显式给出依赖闭包；矛盾组合通过 `#error` 给出缺失条件。旧 `XGE_NO_*` 等宏做兼容映射，检测正负宏冲突；已有使用 `#ifdef` 的正向开关迁移时必须检查值为零的行为。

裁剪覆盖公开声明、实现、控件注册、DLL 导出、源码列表、内置图片和字体、第三方编译及链接。允许保留少量通用类型声明；关闭后的功能入口和大资源不能残留。库与消费者使用同一配置，提供轻量的构建功能标识用于诊断配置不匹配。

### 4.2 配置与输出

| 配置 | 内容 | 用途 |
| --- | --- | --- |
| `core` | 生命周期、窗口输入、必要资源与底座；无高层绘图、文本和 UI | 最小体积与裁剪验证 |
| `2d` | 基础 2D、纹理；高级绘图与 UI 关闭 | 保留轻量二维用途 |
| `3d` | 3D 模型与必要底座；2D、文本、音频、XUI、ShapeEx 关闭 | 开发主路径 |
| `ui-min` | 2D、必要文本、XUI 核心、Panel、Label、Button、Image | 控件精简验证 |
| `full-dev` | 现有默认能力加已完成的 3D | 集成与兼容回归 |

没有显式选择配置时，保留当前默认构建兼容性；新增 3D 默认关闭。轻量应用显式选择精简配置。IDE 和 MAPGEN 等 xrt profile 保留原用途，不能进入最小运行库。

输出隔离到 `build/<profile>/`，配置头、对象、导入库、DLL 和测试使用相同 profile；测试不得加载旧目录中不匹配的 DLL。每个控件应支持单独开启或关闭，并按真实依赖保留基础容器和服务。`ui-min` 不拉入 Document、CodeEdit、WebView、图表、工作流等大模块。

### 4.3 提速实现

保留现有脚本入口，增加共享的功能清单与简单源码选择规则；不迁移整套构建系统。缓存编译对象，键包含编译器、配置、参数、源文件和包含文件依赖。采用编译器生成的依赖信息；不能只检查主文件时间，也不能每次递归扫描全仓库。

新增 3D 文件优先独立翻译单元，通过少量私有桥接函数接入现有上下文。不要把所有新增实现继续包含进 `xge.c`，也不为此拆分整个历史实现。若独立编译遇到私有状态问题，只提取本功能实际需要的访问入口。

默认 3D 快速回归先跑 CPU，再按涉及内容跑 GPU；全 XUI 和文档系统不进入每次 3D 迭代。P0 要验证一次无改动热构建和一次实际源码修改后的增量构建，确保不重编译无关模块；P1 再用新增独立 3D 文件复核这条路径。

P0 的 `3d` 配置先构建必要底座，尚未实现的 3D 入口不声明、不导出，不创建空实现来通过构建。各能力随 P1 至 P5 加入，并同步扩展对应配置与测试。

## 5 最小架构与接口规则

采用 `Scene3D`、Node、Camera、Model、Mesh、Material、Light、Environment、Animator、Renderer。Scene3D 是通用场景容器，不增加沙盒实体或业务组件框架。先用直接结构和 xrt 容器完成实际调用路径。

| 数据 | 首选实现 |
| --- | --- |
| 节点句柄与代次校验 | xrt SlotMap |
| 节点、网格、轨道、绘制列表 | xrt Array 或明确布局的连续数组 |
| 资源与名称索引 | xrt Map |
| 小对象复用与临时数据 | 按需使用 xrt Pool、Buffer |
| 动作配置与离线映射文件 | 已有 JSON 或 XSON，只选实际需要的一种 |

API 使用 `xge3d*` 前缀，创建与加载返回错误码并通过输出参数交付对象。资源采用不透明句柄；Scene3D 拥有节点，节点持有模型引用，多个实例共享资源。借用值、释放顺序、失败后的对象状态必须写入公开注释。

坐标为右手系，Y 向上，米为默认单位，角度为弧度，相机局部观察方向为负 Z。节点使用位置、四元数、缩放；层级变化更新缓存矩阵，拒绝循环父子关系。原文件的矩阵与蒙皮语义必须正确转换，不能强行分解后静默改变模型。

相机和模型矩阵在 GPU 使用；法线变换处理非均匀缩放，负缩放处理绕序。第一次创建和更新上传网格，普通绘制不重新打包全网格。新增顶点支持法线、切线和需要的 UV，索引支持 16 位及 32 位。

GPU 创建、提交和释放先限定在拥有上下文的线程。资源读取、解码和 CPU 计算可以异步，主线程按预算提交。进入 3D 前 Flush 2D 队列，退出后恢复或正确重建后续绘制依赖的深度、剔除、混合、程序、缓冲、纹理、帧缓冲、视口和裁剪状态。所有失败路径也完成恢复。

### P2 模型与静态场景

| 工作包 | 内容 | 验收 |
| --- | --- | --- |
| P2.1 | 固定版本 cgltf；通过 xgeResource 解析关联资源 | GLB、外置资源 glTF、内嵌图片、非索引网格、异常数据处理通过 |
| P2.2 | 材质、节点层级、共享实例、基本透明、天空盒 | 多材质、法线、负缩放、Alpha Mask、双面与基本透明排序符合预期 |
| P2.3 | 屏幕射线、模型拾取与最小场景范例 | 通过 C API 加载、放置和选择多个共享模型实例 |

glTF 解析采用 C99 的 [cgltf](https://github.com/jkuhlmann/cgltf)，它不替代关联缓冲与图片的加载适配。版本、许可证和源码来源在引入时固定。

基础材质采用金属度与粗糙度语义。颜色贴图按 sRGB 解释，法线等数据贴图按线性解释；保留 glTF 未预乘 Alpha，避免复用 2D 的默认预乘路径。贴图缓存键包含用途、色彩空间与 Alpha 方式。读入的步长、索引、节点关系和分配尺寸必须校验。[glTF 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html)

支持清单随实现记录；不能把解析器能识别的所有扩展标成渲染器支持。必需但不支持的扩展明确返回错误，避免静默丢模型。

| P3.4 | 可裁剪静态 IBL、环境输入与昼夜参数范例 | 离线准备环境数据；金属与粗糙材质响应正确；关闭 IBL 可编译运行 |

先采用少量可配置灯光和简单前向渲染，不先写集群灯光。太阳阴影默认沿用一条稳定路径，级联数量及距离可设置。点光源先提供照明。昼夜示例由应用修改光向、天空和曝光参数，库不内置时间或天气系统。

天空盒先支持明确顺序与方向的六面输入。静态 IBL 的预过滤和积分数据由离线工具或可复核的生成步骤提供，运行库不引入完整环境烘焙系统。

P3.3 在 P4 骨骼与 P5 高度场完成后补蒙皮和地形阴影回归；此前记录为待交叉验收。已通过的静态阴影路径允许继续开发后续阶段，最终交叉验收通过后再完成全阶段。

FBX 工具采用固定版本的 C 编译 [ufbx](https://ufbx.github.io/)，复杂曲线使用其[求值与烘焙功能](https://ufbx.github.io/elements/animation/)。BVH 使用范围有限的解析器。转换工具独立链接，不进入 `3d` DLL。

重定向先实现显式人形语义映射、参考姿态校正、局部轴差异、根与骨盆位移及比例修正。保留目标骨长；不能仅按名字复制局部旋转。可用脚部 IK 修正必要接触，避免扩展成通用 IK 图。自动名字映射只是建议，手动映射必须可保存。

验收动作至少包含站立、行走、跑步、跳跃、挥砍和采集。至少一组动作来自项目外部，模型与动作独立输入；两种目标角色要有实际骨架或姿态差异，不能用复制模型完成验收。先验证源动作播放，再验证目标映射，清楚报告缺失骨骼和限制。

骨骼数与权重受实际硬件能力约束，给出查询和错误信息；截断权重时按已声明策略重新归一化并记录处理，禁止静默截断骨架。glTF 轨道支持规定的 STEP、LINEAR、CUBICSPLINE 语义，离线转换可以烘焙为简单轨道。动画事件和根运动输出交给应用处理，库不直接穿透碰撞移动角色。

glTF 不保存一般制作软件的约束控制器。需在导出或转换时求值为骨骼轨道，不能承诺直接复现任何制作工具的控制绑定。

### P5 规模与通用功能支撑

| 工作包 | 内容 | 验收 |
| --- | --- | --- |
| P5.1 | 视锥裁剪、GPU 实例化、应用指定 LOD | 同一模型多实例共享资源；绘制量受裁剪影响；LOD 数据由应用指定 |
| P5.2 | 可裁剪高度场、分块绘制、有限级别 LOD 与查询 | 16 位或浮点高度保留；高度与射线查询符合实际三角形；LOD 边界无明显裂缝 |
| P5.3 | CPU 加载与主线程预算提交、取消和过期结果处理 | 失败不发布半成品；取消后无残留；预算耗尽后正确续接 |
| P5.4 | 相对原点输入、射线与基本重叠查询、应用集成说明 | 原点改变后渲染、拾取与阴影一致；创建、移动、删除模型可供外部模拟使用 |

高度场只管理输入数据、网格、材质和查询。首版采用固定分块和少量 LOD，明确接缝策略；不做通用流式世界管理。全球坐标与分块由应用维护，XGE 定义局部坐标及相对原点转换契约，不能宣称普通 float 场景自动具备无限世界精度。

异步设施复用 xrt 和现有资源方式，GPU 工作保持上下文线程执行。xrt 任务池仅在实际需要的 profile 开启。空间查询先覆盖射线与 AABB、球、三角形、模型和高度场的必要相交；高级扫掠、角色解算、刚体和导航另行评估。

物理与导航在 P0 做小范围技术选型记录。默认本期只交付可操作的几何与变换接口及接入示例；若决定新增成熟后端，必须明确语言、体积和裁剪成本，并由用户授权扩大范围。不能自行添加大型 C++ 引擎，也不能因此阻塞其他必需工作。

## 7 加快长期任务的执行方式

1. 每轮开始只读本文、PROGRESS 的当前项、相关源码和上轮失败证据。首次记录入口与差异后不重复全库分析，不重新讨论已经确定的边界。
2. 一轮聚焦一个可验收工作包，先完成代码与最短运行路径。公共头、构建和内部接口改动及时集成，避免长时间只写框架或测试。
3. 用最简单的正确方案先贯通：立方体先于导入，单张阴影先于级联，同骨架播放先于重定向，同步加载先于预算异步，固定地形先于 LOD。
4. 默认使用 `3d` 精简配置。新增 3D 文件单独编译，沿用已通过的底座对象。只重建被改动及其依赖的对象；不依赖旧 DLL 假通过。
5. 先跑相关的快速测试。阶段收尾或共享代码变动时扩大回归；检查通过且源码未变时不重复完整套件。纯文档或低风险整理不新增实现镜像测试。
6. 保持故障修复以证据为依据。两次同类失败仍无进展时，重新检查最小复现、实际依赖与现有实现，优先换用范围更小的实现。必须项不能靠空实现、关闭验收或改期望绕过。
7. API 与实现一起产生，不先冻结庞大接口。内部需要第二个真实使用场景才抽取通用层。第三方代码只在一处编译，实现细节不暴露到公共头。
8. 记录阶段状态、通过命令与下一步后继续执行，不把完成一个工作包当成长期目标完成。只有用户要求暂停、真实阻碍或目标运行预算限制时才按任务规则停止。
9. 日常实施不反复申请已经授权的仓库改动。新增重依赖、突破轻量边界或删减必需能力时先展示具体成本与替代方案；继续不受影响的工作。
10. 默认单执行者推进。需要其他代理并行时遵循用户授权与环境规则；可分离任务才并行，共享公共头和构建配置由一个执行者集成。

遇到期限或预算不足，按优先级缩短可选效果、优化范围与工具 UI，保持必需接口和验收真实。没有用户给出的日期，不编造截止时间；没有实测，不声称编译或性能已提升若干倍。
