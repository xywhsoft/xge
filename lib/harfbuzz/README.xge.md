# HarfBuzz in XGE text shaping

Pinned version: 14.3.1, commit `ab5ecbb83985034a76214ac0b2b833dcd590d774`.
Source archive: https://codeload.github.com/harfbuzz/harfbuzz/zip/refs/tags/14.3.1
Archive SHA256: `664fee79687413546f94919b8bff5356da88cbc2eacb5dcdb17882ac6f39b41e`.
`src/` is copied unchanged, with its nested license files. See `COPYING`.

The C XGE adapter uses HarfBuzz's C API and existing stb_truetype rasterization.
The dependency is compiled separately as C++17; XGE/XUI/Document source stays C.
`build_text_shaping.bat` compiles the upstream `harfbuzz.cc` amalgamation into a
cached object. `build_dll.bat` enables it in the normal and optional-WebView DLL.
The Windows build uses native mutexes and needs no additional C++ shared
runtime. The Linux dependency probe defines HAVE_PTHREAD and links pthreads;
without that define, upstream selects std::mutex and requires the C++ runtime.
No FreeType, platform font API, ICU or GLib is used. Other build systems can
compile the same object and define XGE_ENABLE_HARFBUZZ; select their native
mutex configuration explicitly. Apple is detected by upstream; Android and
other pthread targets need HAVE_PTHREAD. Those platforms are not yet verified.
An explicitly minimal build without that macro retains the existing simple
glyph path; it cannot prove the full Document font-shaping delivery requirement.

Font instances cache an immutable HarfBuzz font referencing their retained face
bytes. Runs retain their font instances. The shaper supplies GSUB/GPOS glyphs,
source cluster ranges and Unicode-grapheme caret stops; GDEF values are used
for one carrier, including a ligature accompanied by zero-advance GDEF marks,
when the complete list matches the graphemes and is geometrically valid.
Caret coordinates include the carrier's shaped pen and GPOS placement; RTL
stops are leading-edge distances. Missing, malformed or ambiguous mappings
fall back as a whole to equal grapheme stops. Multiple carriers and spacing
marks remain a fallback. A C callback on an immutable OT subfont now supplies
original contour points for unhinted static TrueType GDEF Format 2, including
off-curve points and compound transforms/offsets/real-point attachment. The
same bounded reader feeds cached TrueType rasterizer vertices; upstream HB
and stb sources remain unchanged. Raw GDEF validation rejects failed point
queries and unknown formats as a whole, while retaining valid zero coordinates.
CFF contour-point numbering, hinted/variable contours, phantom-point compound
attachment and device/variation adjustments remain unsupported or unverified.
XRF bitmap-only runs still use their bitmap metrics; SFNT fallback spans shape
with their own retained font. Emoji items keep the existing separate provider.
Ligature paint spans crop the original glyph's destination and UV at the same
grapheme stops; range decorations use those stops as well. Font and run public
struct callers must be rebuilt together with the DLL after this ABI change.

The small TTF fixtures in test/data/xge_opentype_fixture.ttf and
test/data/xge_opentype_points_fixture.ttf are generated from project code in
test/generate_opentype_fixture.py. The latter also has independent FontTools
coordinate and flattened-glyph oracles (.points / .pairs). FontTools is needed
only to regenerate them. No operating-system or externally licensed font bytes
are bundled there.

The adapter shapes direction-resolved LTR/RTL items and preserves logical
source-cluster order separately from physical glyph positions. Document uses
the shared SheenBidi bridge for paragraph analysis, line reordering and basic
visual caret navigation. Generic TextLayout remains logical. Full paragraph/style
context, explicit language itemization, complete contextual font fallback and the remaining Bidi editing
matrix still require work; linking the library alone does not complete them.

The C SFNT adapter now selects the earliest fallback font covering a complete
grapheme or a same-resolved-script word segment. Nominal misses are checked with
real HB normalization/GSUB; Default_Ignorable_Code_Point uses pinned Unicode 17
ranges in src/xge_text_ignorable_data.inc under lib/unicode/LICENSE. Native HB
items receive surrounding context from the supplied string. Unmatched words
cache their failed boundary before trying complete graphemes. The selector uses
the shared C Unicode 17 extended-grapheme kernel and heuristic word segments;
word boundaries are still category-based. Explicit language itemization, bitmap-root
fallback, mixed-font mark composition and context across Document style groups remain pending.
Project-owned cmap subsets are generated by test/generate_font_fallback_fixtures.py;
their glyph outlines and layout tables remain identical to the original fixture.

src/xge_unicode_grapheme.h shares the generated GCB/InCB/Extended_Pictographic
properties and UAX #29 revision 47 state machine with XUI editing and layout.
Script changes cannot split a grapheme even when no fallback font is configured.
The full Unicode 17 corpus, all property codepoints, native Document navigation
and existing GDEF/GPU cases are tested. This does not alter the upstream HB
source or upgrade XUI's UAX #14 line engine.

src/xge_unicode_script.h resolves pinned Unicode 17 Script_Extensions using
set intersection without splitting extended graphemes. Prefix neutrals join
their following compatible run, Common paired brackets retain their enclosing
script (overriding a limited raw SCX set such as CJK angle brackets), and
the bracket stack is bounded at 128 entries (oldest openings drop on overflow).
Unknown/default Common/Inherited are unconstrained; an otherwise ambiguous
set chooses a compatible preceding script, then its primary script, then the
first ISO 15924 tag in the pinned ordering. Paragraph separators reset context.
Native items, complete-word fallback and actual HB coverage probes consume the
same resolved map. ASCII avoids the extra allocation; non-ASCII uses one byte
per source byte. Document no longer cuts these items by first-scalar Script.
The all-codepoint property oracle and project-owned script-specific locl fonts
exercise both plain shaping and real Document GPU rendering.

xge_text_shape_desc_t now accepts a full UTF-8 paragraph, its item byte range,
an optional explicit ISO 15924 script and a BCP 47 language. Item bytes must
match their range in the context; ranges cannot split UTF-8 scalars. Context
is borrowed for the synchronous call and is not retained by the result. The
caller supplies valid UTF-8. Without an explicit script, resolution scans the
full context once per shape call; a supplied script skips that map allocation.
Coverage probes and final shaping use one buffer-property helper, preserve
HB pre/post context and paragraph BOT/EOT, and rebase clusters to the item's
origin before constructing output glyphs and GDEF carets.

Language syntax is checked without allocations using RFC 5646, including its
grandfathered tags and duplicate variant/extension rejection, with a 255-byte
implementation bound. Registry membership is not checked. NULL is explicitly
`und`, independent of process locale; font script/language table fallback
remains HB's behavior. iTextSize=0 is an empty item; -1 denotes NUL termination.
The descriptor ABI changed: callers and DLLs must be rebuilt together. Builds
without HB reject explicit context/script/language instead of claiming support.

The native context tests compare project-owned Arabic/locl/GPOS fonts against
upstream HB with independently supplied scripts and check nonzero-context GDEF
stops. XUI's five text proxy callbacks now share xui_text_item_t and pass
context, item range, script, language and shaping flags to native shaping,
measurement and drawing. XUI_PROXY_VERSION is 11; custom proxies and callers
must migrate and rebuild together. Paint flags cannot override item direction.
Document still needs full display paragraph context across line/style/font/
direction splits and language attributes. That migration must cache paragraph
script resolution, account for filtered
controls and displayed discretionary hyphens, and preserve source offsets;
the shared text request alone does not complete it.

The pinned buffer stores five pre/post Unicode scalars. Long Joining_Type=T
sequences can hide the effective joining neighbor, even with the full UTF-8
paragraph supplied. `src/xge_text_opentype_context.inl` scans only adjacent
transparent scalars and the first effective neighbor on each side. When that
neighbor falls outside the window, it seeds context through public empty
`hb_buffer_add_utf8` calls and appends only the original item with absolute
clusters through `hb_buffer_add`. This keeps ZWJ/ZWNJ effective, leaves
BOT/EOT/script/language unchanged, adds no paragraph copy or owned allocation,
and is shared by final shaping and GSUB coverage probes. Ordinary nearby
context still uses the normal add_utf8 path. No pinned HB source was patched.

Joining transparency is generated from pinned Unicode 17 DerivedJoiningType
data under the existing Unicode license. Independent full-codepoint checks
compare actual C queries with both the official data and HB's own table and
category fallback. Whole-paragraph RTL Arabic oracles and a medial-only
missing-cmap probe exercise the actual native pipeline; XUI GPU tests use
literal PUA glyph aliases. The portable sanitizer test counts reads of a
400006-byte context and releases both borrowed buffers before shaping.
This repairs joining context; it does not make cross-item ligatures/GPOS,
whole-word fonts across styles or Document paragraph projection complete.
